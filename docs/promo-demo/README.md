# Promo demo: Morph Suite

A 2:48 piece built to show functional cables, played by the real `kabl-ui` application and recorded with its audio. Everything here is generated by scripts so it can be re-recorded after the UI redesign.

Status: audio and video are engineering evidence, not owner acceptance. The agent that made them cannot hear. Kosta listened to the audio (v5) and chose it; he has not watched the video.

## Files

| Path | What |
|---|---|
| `morph-suite-promo.mp4` | Final clip: 1920x1080, 30 fps, H.264 + AAC, real app audio, burned-in captions. |
| `morph-suite-audio.mp3` | The same piece rendered offline (no UI), 160 kb/s. |
| `patch/morph-suite/` | The patch, saved by the editor. Open with `kabl-ui --patch docs/promo-demo/patch/morph-suite`. |
| `timeline.json` | When each cable's morph moves, cable ids, section names. Written by `promo_demo`, read by the scripts. |
| `targets.json` | The only UI-specific data: hit-target names and timings. |
| `record.sh` | The one command. |
| `scripts/make-drive-script.py` | `timeline.json` + `targets.json` to a script for `docs/rack-migration/drive.py`. |
| `scripts/post.py` | Finds bar 0 in the recording, checks it against the audio, burns captions, writes the mp4. |
| `crates/ui/examples/promo_demo.rs` | Builds the patch through `PatchEditor`, defines the timeline, renders the audio. |

## Reproduce

```sh
docs/promo-demo/record.sh
```

It builds, regenerates `patch/morph-suite` and `timeline.json`, renders the audio (`morph-suite-audio.mp3`), generates the drive script, starts its own Xvfb (`XDISP`, default `:98`, 1920x1080), plays the patch in `target/release/kabl-ui`, drives it with xdotool, records the screen and the app's audio, and writes `morph-suite-promo.mp4`. Intermediate files (render, recording, drive script and log, screenshots) are in `target/promo-demo/` (`OUT`). Takes about 5 minutes, 3 of them real time.

Needs: cargo, Xvfb, xdotool, ffmpeg with libass, ImageMagick `import`, PipeWire or PulseAudio (`pactl`; a null sink `kabl_rec` is created if missing), python3 with numpy.

Only the audio, no UI:

```sh
cargo run --release -p kabl-ui --example promo_demo -- render out.wav
cargo run --release -p kabl-ui --example promo_demo -- stems     # each cable's own level, for balancing
```

Regenerating the patch rewrites the timestamps in `patch/morph-suite/log.jsonl`.

## The piece

100 bpm, A minor, chords Am F C G one bar each (a `clock.div` chain and a 4-step `seq`). 70 bars. Seven cables carry a pattern A and a pattern B and a morph between them; the piece is those morphs moved by hand, one at a time (the editor shows one cable at a time), in the real UI. Gesture list and exact bars: `timeline.json`.

| Time | Bars | Section | What moves |
|---|---|---|---|
| 0:00 | 0-4 | Intro | Nothing. A sparse, chancy arp and a held pad. |
| 0:10 | 4-31 | Build | Echo send (one throw per cycle to every step), arp level (sparse and chancy to every note), bass level (silent to full), bass filter route (shut to five uneven steps against the eight-step bass), bells (none to a syncopated pattern with chances), pad gate (held to a 16-step chop). |
| 1:14 | 31-36 | Peak | Everything at B. |
| 1:26 | 36-44 | Break | The whole-band cable snaps to pattern A: two stabs a bar. The echoes ring between them. |
| 1:46 | 44-53 | Return | The band cable snaps back (0.4 bar) on the downbeat of bar 44. |
| 2:07 | 53-70 | Outro | Pad back to held, then bass, bells and arp thin out. |

Other modules heard: filters (ladder, SVF), envelopes, LFO on the pad filter, drive on the bass, chorus, reverb, delay, macro as the filter route's source, mixers, gain, clock dividers. The FM and wavetable oscillators are not used: they are in PRs #17 and #19, not on master or in PR #15.

## UI driving, and what is scripted

Real application, real X input: `docs/rack-migration/drive.py` presses and drags with xdotool at the hit targets the app reports (`KABL_HITS_FILE`). No MIDI controller is involved, and nothing here is hardware evidence. The X server is Xvfb, the audio device is a PulseAudio null sink; the machine's own screen and speakers are not used.

Per gesture the script right-clicks the cable (or clicks the route and its Pattern button), opens "Pattern & probability...", aims at "Morph A to B" and drags it over the gesture's duration (`slide` in `drive.py`, 200 points = 100 %). Bar 0 is the moment of a click on the clock's Restart button, so the piece and the script share a clock.

After a UI redesign: update the names and timings in `targets.json` (hit keys such as `cable:{id}`, `menu:cable-pattern`, `fn-morph:{id}`; `open_lead_s`; `restart_latency_s`) and run `record.sh`. If the redesign gives an editor that stays open for several cables, or a way to move morph without the pattern editor, the gesture list in `promo_demo.rs` can stop being sequential.

## Environment used (2026-10-09)

Linux 7.0.0-34-generic, 20 cores; rustc 1.93.0; ffmpeg 6.1.1; xdotool 3.20160805.1; PulseAudio on PipeWire 1.0.5; Xvfb 1920x1080x24; `kabl-ui --rate 48000 --frames 256`, release build; no window manager. Base: branch `claude/functional-cables` head `f7b83b5` (draft PR #15).

## Verified

- `cargo test --workspace`: 683 passed, 0 failed. `cargo clippy --workspace --all-targets -- -D warnings`: clean. (No tests were added: this is an example and docs; the existing golden hashes in `crates/engine/tests/legacy_patches.rs` pass, so no existing patch changed.)
- Offline render is deterministic (asserted by `promo_demo render`); peak 0.868, no clipping. Rendering the patch again after the layout change gave a bit-identical file.
- The recorded audio of the real app: stereo peak -1.9 dBFS, no clipping. Its loudness envelope correlates with the offline render at 0.88 (0.1 s windows, whole piece), and the loudness in each section is a constant ratio (1.33-1.44, ffmpeg's mono downmix) of the render's: intro, build, peak, break, return and outro all keep the same shape.
- The morph values shown in the drawer in extracted frames follow the script (78 % mid-ramp of the bass filter, 97 % after the echo ramp, 99 % after the band cable's return).

## Not verified

- Nobody has heard or watched the final video. The audio is the render Kosta approved, not necessarily identical to what the app plays: the chances in the patterns may play out differently in the live app (not compared note by note).
- Sync between the music, the morph drags and the captions is within about 0.3 s. The music's bar 0 comes from the Restart click time plus a constant (`restart_latency_s`), the captions use the lag measured from the audio envelope; the drags use the constant only. Not measured to the sample.
- A real laptop speaker, real hardware, the CLAP plugin and other hosts were not tested.
- The video is a screen capture of a 50 % zoom rack: the text on the modules is small. The patch editor shows one cable at a time and does not highlight the cable being edited.
