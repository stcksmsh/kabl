# D10 panel design and compatibility

## Representation and identity

An optional boxed Panel lives on each D09 Composite. The box keeps the existing operation enum compact; serialization is an ordinary optional object. Older composites omit it and load with their original face. Each placement is keyed by an immutable exposed interface ID, never a label, coordinate or array position. Its kind is knob, selector or jack; its footprint includes printed labels and values. Bindings remain the original PortRef aliases. Renaming and moving presentation never rewrite leaf IDs, pins, cues, CC keys, cables or native automation lanes.

Panel width is 180–840 rack points in 30-point units. Height remains 340. The top 64 and bottom 32 points reserve the instrument title, Inspect internals, Design and Public controls/help. A continuous parameter binds a knob; a stepped parameter binds a selector with at least 18 points per choice. Jacks bind public ports, including parameter modulation inputs. Minimum footprints and non-overlap are validated before one existing SetComposite transaction is committed. The face's world geometry is shared by rendering, focus/reveal and screen transforms, so zoom and native display scaling do not introduce a second coordinate model.

The authoring window stores a draft separately. Apply validates the complete candidate and changes labels plus panel in one chronological project Undo step. Preview switches the existing theme and shows the applied face. Reload restores the current saved face; Use default face removes metadata with Undo. Instance tools continue editing help, exposed targets and immutable publication. Removing an exposure removes its placement in the same transaction. Projects and host state embed the complete panel; standalone history remains chronological, and host recall still does not promise a persistent Undo stack.

## Assets and trust boundaries

Artwork is embedded PNG data plus a simple local name. No package file paths are interpreted or extracted. Names accept ASCII letters/digits, dash, underscore and dot, excluding empty, dot and double-dot. Separate light/dark images are optional. Each PNG is capped at 128 KiB, 2048 pixels per edge and one megapixel. The current document is capped at eight megapixels across both variants (32 MiB RGBA). Existing D09 graph, serialized package and host-state caps still apply; the actual serialized cap can reject a collection before individual asset limits are reached.

Import reads only the cap plus one byte. Core validates dimensions/geometry and aggregate memory before the control-side image decoder runs. UI/package and complete host-state validation decode PNGs before mutation. A malformed package, incompatible binding or overlap leaves state, history and ID counters unchanged. Library reads now use the same bounded package reader. Export refuses an existing destination rather than truncating it; immutable publication retains D09 staging/validation/hard-link semantics and never retargets an instance. This is not a crash-durable fsync guarantee.

Missing artwork uses a procedural face and an actionable Public controls/repair affordance. Arbitrary art cannot make labels unreadable: small opaque label/value strips use the first decoded pixel's material tone, with black or white ink selected for contrast. Long labels are shortened to their footprint; full jack labels and targets remain in tooltips, and full public labels remain in fallback UI. All exposed parameters remain reachable with native accessible sliders/selectors in Public controls; unplaced ports remain connectable there. Cables to unplaced ports dock at the fallback affordance until the port is placed. That docking is an explicit compact representation, not a guessed hidden control position.

Texture creation, decoding, file access, validation and cache retirement run on UI/control threads. The cache drops images when their current document artwork changes or disappears. No image bytes enter the audio messages or compiled nodes. D08 callback ownership, bounded producer/consumer contracts and deferred graph retirement remain untouched. The vendor profile and its upgrade obligations remain authoritative. Undo history can retain prior embedded images; the current-document decode budget is not a bound on all retained project history.

## Selected material treatment

Kosta selected V3 continuous colored faces and the generated study's satin material. Built-ins keep exact rack/control geometry and use original sectional colors: terracotta oscillator/noise, sage filter, lavender modulation/envelope, sand VCA/mix and cool pale timing/MIDI. Dark variants retain geometry and use muted versions with light printed ink. Procedural coating uses one lighting direction, restrained grain and thin edges. Knobs are charcoal with fine grip marks and a modest rim; jacks are recessed. Large dark output blocks are replaced by fine grouping rules. Routing, state colors and their textual explanations remain the existing behavior.

Chrome becomes coherent graphite; the existing filtered sound browser keeps its navigation behavior. IBM Plex Sans/Mono are embedded under OFL-1.1 so label metrics survive a fresh profile or missing system fonts. No render bitmap, reference image, new framework or dependency was imported. The example backgrounds are original editable SVGs with deterministic PNG exports, licensed under the repository's MIT OR Apache-2.0 terms. The generated material study remains an aesthetic reference, not application evidence or an asset.

## Limits

The GUI uses precise numeric placement instead of a new canvas editor or drag/resize subsystem. This meets the bounded authoring scope without duplicating rack hit testing. Preview uses applied metadata; it is not a live unsaved-draft preview. Unplaced controls use fallback rather than guessed placement. Arbitrary multi-row faces, D11 runtime and marketplace remain excluded. Material fidelity is a renderer adaptation of the reference, not physical-render parity or owner finished-product acceptance. Earlier listening, controller, latency/feel, ordinary-render nondeterminism and dense-editor backend/performance limits remain open.
