# D09 composite design

## Representation and compilation

PatchState keeps the original flat modules and cables. A typed composite record owns a disjoint set of leaf IDs and optionally has a parent composite. Every public port/control has an immutable numeric interface ID and points to a concrete existing PortRef. Group IDs occupy a distinct namespace; group identity and definition identity/version are separate. Grouping adds metadata without rewriting leaf or CableIds, positions, controller targets, native automation targets or cue references.

The compiler validates ownership, ancestry and real built-in bindings, then compiles exactly the existing flat graph. There is no wrapper DSP node, recursive engine, block adapter or new delivery mechanism. Existing scheduling, cable-ID accumulation order, delayed feedback, voice-to-global rules, polyphony and reset behavior remain authoritative. Metadata-only operations do not trigger runtime graph rebuilds. Exact PCM tests include feedback across a boundary, polyphonic note/release events, stereo effects and guarded allocation-free processing.

An instance embeds its complete definitions and leaves. Nesting is an ownership tree, bounded to eight levels. Parent cycles, missing parents, multiply owned leaves and repeated exact definition identity/version on an ancestor path are rejected. Reusing a definition in siblings is allowed. Embedding fully materializes nested leaves rather than consulting a recursive library resolver.

## Identity and independent editing

SetComposite is a typed invertible project operation. Encapsulation, insertion and duplication validate and compile a candidate before applying one Group transaction. Failure changes neither document, log nor ID counters. Interface counters never reuse removed IDs. Module/cable/group allocation scans retained forward and inverse history as well as live state so deleted or undone objects cannot collide with a later copy. Removing a leaf prunes its ownership/exposures, and Undo restores exact metadata and routes; label deletion has no ownership side effect.

Public controls are aliases of original parameters. Existing param_editor handles gestures, requested bases and log coalescing; the CLAP editor continues detecting the same native leaf targets. No second value model is introduced. Opening and closing is view state, not an audible edit. Cards pack against rendered rack occupancy without moving stored leaves; Fit accounts for cards. A copy gets separate leaves and internal cables, copied state and fresh pin order, but no external cables, CC/button mappings or native lane assignments. Autogenerated target labels are remapped; custom labels stay unchanged.

External routes retain their original endpoint and cable identity during encapsulation. Boundary aliases are deduplicated by exact target. Removing a connected boundary exposure is refused until its crossing routes are disconnected. Pins, original cue/launch references and native lanes remain attached to original leaves. Same-project copies remap internal cue/clock references and preserve external references; float-encoded clock IDs must remain exactly representable.

## Persistence and libraries

Standalone schema v4 adds SetComposite while accepting existing v1–v3 flat logs. Current log replay validates the final ownership tree before returning to any loader. State-based editor seeding adds the entire ownership tree as one atomic Group so Undo cannot orphan nested children. Current log replay remains source of truth; checkpoint is still only a convenience snapshot. CLAP SoundState v3 carries complete composite metadata using unchanged complete-state publication; v1/v2 remain accepted for flat states and reject active composite data. Flat snapshots still emit v2. Host recall preserves complete sound, lanes and native base values, not a persistent project undo stack.

Package schema v1 contains one root and every descendant/owned leaf/internal route. Decoding rejects incomplete ownership, unknown package schema/kind, duplicate semantic map/member IDs (including nested label keys), invalid binding/metadata, recursion, missing dependencies and graph/byte/effect bounds before mutation. Cue/clock dependency errors name the module and target and instruct inclusion. Publish/import only accepts a closed dependency set; no silent dangling references or guessed bindings.

Library versions are immutable JSON files in the existing user root. Publishing validates serialized bytes, writes a unique staging file, reads/validates it back and hard-links without overwriting a version. It does not retarget any instance, including the instance that supplied the snapshot. The project remains sufficient after the original library is missing or updated. This is not a crash-durable/fsync filesystem guarantee; a completed version cannot be replaced by the application.
