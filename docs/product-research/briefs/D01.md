## Scope

- A searchable patch browser with explicit Factory and Your Sounds areas, a small category/tag vocabulary, favorites and recents. Show playable voices and self-running/transport-driven pieces distinctly. Keep metadata simple and local; a database is not presumed necessary.
- Discover the six existing palette voices and existing composition demos without entering repository paths. Supply a simple initialized keyboard patch. Preserve factory sounds unless a separately authorized repair requires a change.
- Audition keyboard voices with a clearly labeled note/chord control. Define note, velocity and duration in the UI/help; do not pretend a fixed preview demonstrates every sound's range. Start/stop sequence patches explicitly using the existing transport. Do not auto-start sound merely by moving browser focus.
- Load the selected sound into the normal editor and reuse its existing Perform controls. Do not build a second parameter state or implement D02's help/routing presentation here.
- Save As a personal sound, reopen it, rename it and find it again. Prevent normal Save from overwriting factory content. Clearly handle an existing user name/path rather than silently overwriting it.
- Protect unsaved edits on load/new/quit. Distinguish saved-document changes from the existing audio-rebuild dirty flag and transient playback state. Define and test undo back to the saved state; don't derive “unsaved” from whether a callback rebuild is pending.
- Discover factory resources when launched outside the source checkout. Choose a documented Linux user-data location and a reproducible resource-install/package layout; an optional explicit path override is fine. Keep the existing advanced path workflow if useful, but it is not required for normal use.
- Fix active documentation describing the old path-only workflow or stale module count where affected. Preserve historical evidence and owner-review states.

## Compatibility and failure behaviour

Existing patches and the log-based source of truth remain supported. Do not replace the patch format wholesale to add browser tags. Current save uses multiple files: explicitly design safe commit/recovery behaviour for the authoritative data and optional browser metadata. A failed metadata update must not destroy a valid sound. Document guarantees honestly; do not claim power-loss durability without implementing it.

Parse, validate and prepare a loaded patch before committing to replacement. A malformed/uncompilable patch or failed save leaves the working sound and unsaved edits available. Missing factory resources or a read-only user directory produces an actionable error and a usable application, not a panic. Loading must use fresh-graph semantics, not carry old notes/tails into the new patch inadvertently.

Preview notes use the existing audio-thread keyboard path. Identify and bound the preview lifetime; stop on explicit release/stop, load, applicable focus loss, device change and shutdown. Avoid stealing/releasing physical-controller notes unnecessarily; document the source interaction and verify overlaps. Do not route every note through GUI polling as a new production MIDI design. Preserve sustain, panic, mono/poly/legato, existing clock semantics and keyboard ownership.

No audio-thread file I/O, blocking, allocation or unbounded queues. Browser scanning/saving must not move work onto the callback. Patch identities must not rely solely on display names; handle duplicate names and missing recent entries explicitly. Favorites/recents are library preferences, not sound parameters or audio undo operations.
