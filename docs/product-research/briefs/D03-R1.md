## R1 — Full stream-error queue leaks owned messages without a total bound

Source:
- crates/standalone/src/lib.rs::hand_off_stream_error
- crates/standalone/tests/rt_with_logging.rs::audio_side_paths_do_not_allocate_with_trace_logging
- D03 REVIEW, F5 and its recheck.

Observed in code, not newly executed by the supervisor:
The hand-off moves cpal::Error into an rtrb queue; on Full(e), it increments lost and calls
std::mem::forget(e). Message-less xruns are now excluded, but non-xrun errors with owned
messages still take this path. Each overflow retains that allocation permanently.
A 256-slot queue limits queued errors, not allocations forgotten after overflow.
The existing test creates 400 owned messages against capacity 1 and expects 399 to be
forgotten; it tests RT allocation/deallocation avoidance, not bounded lifetime memory.

D03 requires bounded buffering and safe stalled-consumer/overflow behavior. A reviewer
calling the leak bounded does not satisfy that requirement. Event rarity is not a bound.

Required:
1. Establish the actual cpal 0.18.2 error ownership and callback-thread behavior for the
   supported Linux backend(s), using pinned source and/or official documentation. The test
   comment "Made off the audio thread, like cpal does" needs evidence; distinguish backend
   allocation from application behavior.
2. Replace the unbounded ownership escape with a bounded, justified error-handling policy.
   Count/coalesce repeated events and preserve useful error classification. Text may be
   truncated or omitted when necessary; disclose what is retained.
3. Preserve the original no-blocking/no-formatting/no-file-I/O RT contract. Do not silently
   replace the leak with callback deallocation, an unbounded deferred-free list, a larger
   queue or a blocking writer.
4. If the backend's owned-error API cannot satisfy every original guarantee, return the
   precise incompatibility and smallest proposed contract adjustment with source evidence.
   Do not hide it behind mem::forget or claim a universal guarantee the backend cannot meet.
   Continue other useful closeout work; supervisor/owner resolves a consequential tradeoff.
5. Add a regression that covers repeated overflow while the consumer is paused, then
   recovery/drain and shutdown. Verify bounded outstanding ownership, not RSS alone or only
   a no-allocation assertion. Count dropped events accurately. Test both binaries'
   relevant hand-off paths or establish their shared use.
6. Update README/design/REVIEW/REPORT guarantees and limits. No "bounded leak" claim without
   an actual total bound.

Scope is the diagnostic error-handling path. Do not implement automatic stream restart,
device recovery, a general logging framework or the D05 fault-injection project.
