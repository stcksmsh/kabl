# D12 — supported creator SDK and portable code packages: planning brief

Date: 2026-11-08. Status: **planning only, for Kosta's approval. No product code, no launch implied.**
Base: origin/master b772a76e (D11 PRs 1-5 merged; PR 6 in flight, so ABI facts below may shift by small edits). Sources: `docs/PRODUCT-PLAN.md` D12, `briefs/D11.md`, `briefs/D11-DECISIONS.md`, `docs/design/verdicts.json` (D11 notes on migrate, FTZ/DC, state_save/state_load), `crates/modules/src/code/`, `crates/modules/code-examples/`, `crates/core/src/embedded.rs`.

## 1. Outcome and out-of-scope

Outcome: a developer who has never seen kabl's source can, from the published SDK instructions alone, create a distinct useful module, build it with one command, load it, save and reload a patch, share it as a file, and get a clear error when something is wrong. Acceptance is the PRODUCT-PLAN one: a fresh agent given only the SDK docs does this; the module survives save/reload, automation, polyphony (if advertised) and host render; an old project keeps its exact module version or fails with an actionable "missing module X v3" report.

Out of scope: a store, accounts, payments, signing infrastructure; real-time file/network access; compilation inside kabl; Faust (cut by the owner); factory sounds; non-Rust source languages as supported routes (the ABI is language-neutral, but only Rust gets a crate, template and docs); GUI authoring tools; wasmtime; any "unrestricted performance or freedom" claim.

## 2. What the code gives us (measured from source)

- **ABI v0** (`abi.rs`): `ABI_VERSION = 0`. Required exports `init(sample_rate: f32, max_block: i32) -> i32` (address of nine LE u32 words: input, output, params, state, state_len, max_block, in_slots, out_slots, n_params), `process(n_frames: i32)`, `reset()`, and `memory`. One f32 per param per block; host does modulation and smoothing. No imports are allowed (`ALLOWED_IMPORTS`). Caps: blob 2 MiB, memory 4 MiB, fuel 25 % per module / 50 % total of the block period.
- **Metadata** is a `kabl.meta` custom section holding line-based text (`parse_meta`, `wasmi_engine.rs:311`): kind, version (required, starts at 1), name, explain, category, rate, width, `port in|out type name width`, `param name min max default taper smoothing_ms [unit]`, `advanced`. `CodeMeta` is validated and leaked once into a `&'static ModuleInfo`. **There is no help-text, panel, skin, per-param description, or presets/exposure section.** The two example panels exist host-side, not in the module.
- **Declared but not called:** `state_save` / `state_load` are named constants in `abi.rs` and never invoked anywhere in `crates/` (grep, 2026-11-08). State is today the `Layout.state` region of linear memory. `embedded.rs` already stores per-instance kept state keyed by `(instance, version)` (cap 4096) and `version_changes()` produces the "updated from v3 to v4: settings reset" notice. So the host-side half of migrate exists; the module-side half and the state round trip do not (D11 PR 6 may add the round trip; confirm before PR 3 below).
- **Embedding** (`embedded.rs`): blobs in extra skippable `.kabl` frames, SHA-256 identity, max 256 blobs, 2 MiB each, instances bound by hash, one-time Open/Cancel notice per hash. A build that does not know the frames skips them. This is already a per-patch portable unit; it is not yet a per-module installable unit.
- **Examples** (`code-examples/`): own cargo workspace (not part of kabl's), `no_std`, `#[link_section = "kabl.meta"]` static built by a hand-written `const fn bytes`, a `static mut MEM` laid out as `#[repr(C)]` with input/output/params/state, `panic = "abort"`, lto, `strip = "debuginfo"`. `build.sh` copies two blobs to `src/code/examples/`; `tests/code_examples.rs` checks them. Sizes: `demo_logic.wasm` 42,758 B, `demo_bitfilter.wasm` 44,352 B. In `demo_logic.wasm` the data section is 41,376 of 42,758 bytes (section scan), i.e. the buffers are shipped as data. Likely cause is the initialised `static mut MEM`; an SDK memory type should avoid this (spike in section 6). Still 5 % of the 2 MiB cap.
- **D11 report numbers the SDK must respect** (`docs/product-research/d11/REPORT.md`): wasmi real kernel about 1.0 us per 64-sample block per voice (about 1.2 % of block for 16 voices); fuel to wall-clock varies about 2x with instruction mix (1,327 fuel/us spin vs about 3,000 for the real kernel); persistent denormals cost wasmi 13x (12.2 vs 0.93 us) unless the host sets FTZ/DAZ, and the engine did not set it at the time. The FTZ guard is a separate PR already specified in verdicts.json. Until it lands, the SDK must tell authors to expect slow denormals and not rely on a DC-offset workaround.
- **Panels:** `core/panel.rs` is composite-only (`Placement` keyed by exposure id; PNG ≤ 128 KiB; `Panel::validate(&Composite)`). A code module is a leaf, so its panel must be derived or declared against its ports/params.

## 3. The SDK surface

Principle: the SDK writes the boring parts so a creator writes `process`. Three artefacts, one repo path (`sdk/`, new top-level dir, own licence file, outside the kabl workspace like `code-examples/`).

**3.1 `kabl-module-sdk` crate** (`no_std`, Rust, wasm32-unknown-unknown):
- A `Module` trait: `const META`, `fn new(sr: f32, max_block: usize) -> Self`, `fn process(&mut self, io: &mut Io)`, `fn reset(&mut self)`, optional `fn save(&self, out: &mut StateWriter)`, `fn load(&mut self, version: u32, bytes: &[u8]) -> Result<(), Reject>`, optional `fn migrate(old_version: u32, bytes: &[u8], out: &mut StateWriter)`.
- A `kabl_module!(MyType)` macro that emits the exports (`init`, `process`, `reset`, `memory`, state exports), the `Layout` record and the `kabl.meta` section, replacing hand-written `static mut MEM` and the `const fn bytes` hack. `unsafe` stays inside the crate; a creator writes none.
- `Io` gives typed slices: `io.in_audio("in")` style by index constants generated from the declaration, so a port rename is a compile error rather than a silent swap. Params read as `io.param(P::Cutoff)`.
- Meta is a Rust `const` builder (`Meta::new("author.name", 1).port_in(...)...`) serialised to the existing text format at compile time. This keeps the host parser as the single format and adds fields compatibly (section 4). Chosen over a separate `kabl.toml` so a module cannot disagree with its own code; a manifest file still exists for packaging (3.3).
- Buffer helpers: fixed `Smoother`-free (host smooths), denormal-safe `flush(x)` utility, `no_std` math (`libm`), no allocator by default. An opt-in `alloc` feature with a bump arena sized at init (module declares its memory up front; decision 9).

**3.2 `cargo kabl` build tool** (subcommand binary, also a plain script for CI):
- `cargo kabl new <author.name> [--audio|--control]` copies a template (`sdk/template/`) with a working example, one test, README.
- `cargo kabl build` runs `cargo build --release --target wasm32-unknown-unknown` with pinned flags, strips, then runs **`validate`**: no imports, required exports, layout checks (`Layout::validate`), metadata parse, size ≤ 2 MiB, memory ≤ 4 MiB, and a smoke render (silence, impulse, extremes, NaN input; asserts finite output and a fuel figure).
- `cargo kabl test` loads the blob in the real `WasmiEngine` through a small host crate `kabl-module-test` (published from kabl's own `code` module; see section 8 for the licence consequence) and renders offline: golden hash, parameter sweep, 16 voices, reset, save/load round trip, a determinism check (two instances give identical bytes).
- `cargo kabl pack` produces the package (section 4).

**3.3 Docs.** One `SDK.md` (≤ 400 lines, runnable end to end) plus the generated reference from the crate's rustdoc, a limits table (memory, fuel, ports, params, widths, sample rates, block sizes, no clock/rand/threads) and the failure table (every `LoadError`/`Fault`, its message, the fix). Panel/exposure metadata and help live here too (section 4.3).

## 4. Package format and versioning

**4.1 Package = one file `*.kablmod`** (zip, stored, no compression tricks): `module.wasm`, `manifest.json`, optional `panel/light.png`, `panel/dark.png`, `README.md`, `LICENSE`, `CHANGELOG.md`. The manifest repeats what the validator derived from the wasm so it can be shown before loading: `id`, `version`, `abi_major`, `abi_minor`, `name`, `author`, `licence` (SPDX), `sha256` of the wasm, `min_kabl`, `description`, `capabilities` (empty list in v1), `resources` (memory, instances, declared worst-case fuel). The wasm is authoritative; a mismatching manifest rejects the package. A patch continues to embed only the wasm (+ hash), as today; the package is the distribution wrapper, installed to a user module directory and offered in the browser as a new module.

**4.2 Versioning promises.**
- **ABI** `major.minor`. Major breaks exports or layout; minor only adds optional exports and optional meta keys. The host accepts any module with the same major and `minor ≤ host_minor`; it ignores unknown optional meta keys that are marked optional and rejects unknown required ones with a message. ABI v0 is **not** frozen; the proposal is to define v1 = v0 + `state_save/load/migrate` + meta additions, then freeze. Promise: v1 modules load in every kabl 1.x; at most one prior ABI major is kept loadable for one deprecation window.
- **Module** `id` is author-owned and stable; `version` is an integer. A patch records `(id, version, hash)` (already true). Opening a patch with the exact embedded blob always works (the blob travels in the patch); this makes "exact version retained" free. The only failures are: embedded blob refused by the user (Cancel), ABI major not supported, or the blob invalid. Each gets an actionable message with id, version and hash.
- **State.** Module owns its state format. Save writes `version` + bytes. On version change the host (a) offers `migrate(old_version, bytes) -> bytes` if exported; (b) otherwise resets to defaults and keeps the old blob in the patch (existing D11 decision 7 behaviour). A `migrate` that traps or returns invalid bytes counts as "no migrate" for that load, never a crash of the instrument.
- **Compatibility test.** CI keeps a corpus of ABI-major-1 golden modules built by past SDK versions and loads them with every host build. This is the main guard for the "version compatibility" risk (section 6).

**4.3 Presentation metadata.** Extend `kabl.meta` with optional lines: `help <param> text`, `group`, `advanced` (exists), `unit`, `skin <name>` and `panel <kind> <port-or-param> x y w h`, which map to the D10 `Placement` shapes (`Knob|Selector|Jack`) so the UI needs no special case. Artwork stays PNG ≤ 128 KiB in the package. The host synthesises exposures from ports/params; creator-supplied placements are validated against them.

## 5. Creator workflow end to end

1. `rustup target add wasm32-unknown-unknown; cargo install kabl-sdk-cli`. Verify: `cargo kabl doctor` checks toolchain, target, version pinning.
2. `cargo kabl new acme.chorus --audio` → compiles and passes tests on first run (template ships a working effect).
3. Edit `src/lib.rs`: declare ports/params with the builder, write `process`.
4. `cargo kabl test`: offline render, golden hash, fault matrix (trap, spin, NaN output builds are generated by features of the template), cost report in % of block at 48 kHz.
5. `cargo kabl build` → `target/kabl/acme.chorus-1.kablmod`.
6. Load: drop the package into kabl's user module directory (or `File → Add module…`); the module appears in the browser with an "installed, unverified code" badge; first use shows the existing Open/Cancel notice.
7. Save patch; reopen on a clean profile (blob travels in the `.kabl`, no install needed). Remove the install and reopen: the patch still works.
8. Share: send the `.kablmod`, or send the patch alone. A new version `v2` with a changed param list ships with a `CHANGELOG.md` entry; the validator can diff two versions' meta and warn on breaking changes (removed port, narrowed range, changed unit).
9. Errors: every failure above has one line of cause and one of remedy, produced by one table in the host and re-used by the CLI.

## 6. Measurement plan and pass gate

Risks, in order: **(1) version compatibility** (a frozen ABI that later needs a break; patches that stop opening); **(2) creator burden** (toolchain, `unsafe`, unfamiliar `no_std`, big blobs); (3) fuel mismatch makes cost reports misleading; (4) documentation drift.

| Test | Pass |
|---|---|
| **Fresh-agent run** (the acceptance test): an agent with only `SDK.md` and the crate builds a module distinct from the examples (e.g. wavefolder or step-gate) with a panel | Builds, `cargo kabl test` green, saves/reloads, 16-voice render; wall-clock and number of corrections logged. Pass: ≤ 30 min and ≤ 3 doc defects found; each defect is filed and fixed before the beta label |
| Same run by a human Rust developer unfamiliar with kabl, if Kosta can supply one | Same pass, ≤ 60 min |
| Source size of template module | Library hides all `unsafe`; template `lib.rs` ≤ 80 lines excluding DSP |
| Blob size | Template ≤ 16 KiB, bitfilter-equivalent ≤ 20 KiB (down from 44 KiB); report the data-section cause |
| Build reproducibility | Two builds byte-identical on the pinned toolchain; CI checks it |
| ABI compatibility corpus | Every historical golden module loads and renders bit-exact on current host |
| Migrate | v1→v2 state migrates exact; trap/garbage migrate falls back to defaults + kept blob; instrument stays up |
| Hostile modules | forbidden import, oversize, wrong ABI major, bad meta, overlapping layout, memory.grow: all rejected on the control thread with the table's message |
| Automation and polyphony | Param automation bit-exact on offline render; 16 voices × 4 SDK modules passes the D11 allocation check |
| Package validation | Manifest/wasm mismatch rejected; zip path traversal and zip bomb rejected; a package is ≤ 4 MiB total |
| Cost report vs measured | SDK-reported % of block within 2x of the render-measured figure (fuel variance is known, so only the order of magnitude is promised) |

Spikes needed before PR 1 (throwaway, outside the repo): (a) data section size with `MaybeUninit`/zeroed `static` buffers vs the examples; (b) a proc-macro-free `macro_rules!` version of `kabl_module!` compiles under rustc 1.93 on wasm32 with no extra crates. Result decides PR 1 size.

## 8. Dependencies and licences

- Existing: `wasmi` (MIT/Apache-2.0), `sha2`. All pass `deny.toml` (verified for the D11 tree).
- New, SDK crate: none required (`libm` MIT/Apache-2.0 optional). CLI: `zip` (MIT), `serde_json`, `clap` (MIT/Apache-2.0); each to be run through `cargo deny` in the PR.
- **Licence of the SDK crate is the main legal question.** kabl is GPL-3.0-or-later (`deny.toml`, `Cargo.toml`); a creator's wasm links the SDK crate. If the SDK is GPL, every shared module is GPL-bound (strong copyleft on creator work). The usual route is a permissive SDK licence (MIT/Apache-2.0) for the crate and template only, with the host unchanged. Needs Kosta's decision (open decision 3). A GPL host loading a non-GPL wasm module through a defined ABI is not linking in the usual sense, but this is not legal advice and should be reviewed.
- Toolchain: Rust stable + `wasm32-unknown-unknown`; pin the minimum rustc in the template (`rust-toolchain.toml`); the local rustc is 1.93.
- Faust: not used.

## 9. OPEN DECISIONS for Kosta

1. **Freeze point for the ABI.** (a) Freeze ABI v1 now, then build the SDK. (b) Ship the SDK as "beta, ABI may change" with a deprecation window. (c) Wait for REAPER and real-world modules before any freeze. **Recommend (a) after D11 PR 6 lands and one fresh-agent run on v0**; the compatibility corpus makes a later v2 survivable, and an unfrozen SDK has no value to a creator.
2. **Metadata form.** (a) Keep `kabl.meta` text and add keys. (b) Move to CBOR/JSON. (c) Both: Rust builder emits text, the manifest carries JSON. **Recommend (a)+(c)**: one format in the wasm, JSON only in the package; cheapest, already parsed.
3. **SDK licence.** (a) MIT/Apache-2.0 for crate and template. (b) GPL-3.0-or-later like kabl. (c) LGPL-style exception. **Recommend (a)**; ask a lawyer once before publishing. It decides whether creators may sell closed modules.
4. **Package format and location.** (a) `.kablmod` zip as in 4.1. (b) a bare `.wasm` (meta already inside) plus optional sidecar. (c) kabl-specific directory only. **Recommend (a)**; (b) is too thin for README, licence, panel art and checksum.
5. **Trust and signing.** (a) Local packages only, hash shown, one-time Open/Cancel (today's behaviour). (b) Optional detached signature, trusted author list. (c) Mandatory signing. **Recommend (a) for D12**; (b) belongs with a future store proposal, which PRODUCT-PLAN keeps separate.
6. **Languages.** (a) Rust only supported; ABI documented for others. (b) Rust plus AssemblyScript/C template. **Recommend (a)**; every supported language multiplies docs, templates and fresh-agent tests.
7. **Where migrate runs.** (a) Module-exported `migrate(old_version, bytes)` as proposed. (b) Declarative field mapping in meta. (c) Defaults only, forever. **Recommend (a)** with the trap-falls-back rule; (b) is much more host code for little gain.
8. **Capabilities in v1.** (a) None; list is empty and reserved. (b) A `capabilities` list gating future host imports (e.g. tempo, MIDI clock). **Recommend (a)**; the list reserves the field so (b) is a minor bump. Anything with timing, random or clock needs its own D11-style gate.
9. **FTZ/DAZ dependency.** (a) SDK docs say denormals are the host's job once the guard lands; the validator runs a denormal-flood test and reports it. (b) SDK adds `flush()` and recommends use everywhere. **Recommend (a) plus (b) as an optional helper**, and the FTZ PR must land before the SDK beta (verdicts.json).
10. **Scope of "polyphony where advertised".** (a) Module declares `rate voice` or `global` and `max_instances`; kabl enforces (today's). (b) Add a per-module polyphony claim tested by the validator (16 voices render). **Recommend (b)**: cheap and it is part of the acceptance sentence.
11. **Where the SDK lives.** (a) `sdk/` in the kabl repo. (b) A separate public repo. (c) Both: separate repo that vendors from kabl on release. **Recommend (a) until the first fresh-agent run passes**, then split (b) with CI against the kabl release.
12. **Creator-facing cost figure.** (a) Report % of block at 48 kHz/64 from fuel plus an offline wall-clock render, labelled "estimate". (b) Only wall-clock. (c) Nothing. **Recommend (a)**; D11 measured a 2x fuel variance, so the label matters, and no "real-time safe" claim is made.
